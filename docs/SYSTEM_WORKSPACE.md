# 系统架构工作区

本页记录第一版单上游架构。最新版本已扩展为 [多源辅源供电网络](AUX_POWER_NETWORK.md)，旧工程自动迁移；新合同和多源预算以新说明为准。

2026-10-31。桌面和独立网页版启动后先显示系统架构；每个电源模块继续使用原 Python 计算内核和原完整设计界面。

## 使用

1. 默认显示一个输入源和原 40W CCM 反激模块。也可打开原电源 JSON，它会成为系统中的独立模块。
2. 增加输入源，填写电压下限、上限和可供功率；增加电源模块，各模块最多六路隔离输出。
3. 拖动节点改变位置；从输入源 DC 或某模块 OUT 端口连接到下级模块 IN。也可选中模块后在右侧选择输入来源。禁止循环供电及不存在的输出端口。
4. 连线定义供电关系。点击“沿用上游电压”才更新下级 Vinmin/Vinmax，避免连线操作改写已有设计。来自变换器的电压采用各路标称估算值；交叉调整率范围在单元内复核。
5. 双击电源模块，或点击“进入完整设计”。拓扑、器件、曲线、磁件、环路、仿真导出等原功能继续在单元内部使用。点击“返回系统架构”，或关闭单元窗口，参数回存当前模块。
6. 保存系统工程 JSON，文件包含所有模块配置、连线及位置。旧单元 JSON 仍可在单元内单独打开和保存。

支持最多 24 个输入源及 24 个电源模块。节点可直接删除，提供一级撤销；删除上游或减少输出端口会断开受影响的下级连接，保留下级参数。重新连接过的下级不会被撤销操作覆盖。

桌面自动恢复文件：`%LOCALAPPDATA%/PowerDesign/system-workspace.json`。网页版使用当前本机地址下浏览器的本地存储；改变端口或浏览器不共享恢复数据。独立 JSON 是跨电脑、跨入口交付方式。新建工程之前应保存需要保留的工程；自动恢复只保留当前工程。

## 系统检查与报告

功率预算采用各单元总输出配置功率 / 预设效率。直接子模块输入需求占用对应上游端口容量；不将级联功率重复计为外部输出。输入匹配检查验证设计 Vin 范围是否覆盖输入源或标称输出电压。

“生成系统报告包”在后台重新计算各模块，输出系统架构与功率预算总览 Word、每单元 Vinmin/Vinmax 的完整 Word 和 Excel、系统 JSON 与交付状态清单。失败单元列出原因，不能把 ZIP 存在当成全部计算成功。单元内仍可导出原设计或 LTspice 对比报告。

桌面报告在独立进程运行，可以取消；拖动、连线仅更新架构，不执行周期求解。单元详细计算窗口一次打开一个，返回时释放计算任务与图形资源。系统层目前处理供电架构、接口和容量，不计算整机启动时序、掉电保持和多个电源的动态耦合。

## 代码边界

| 文件 | 职责 |
|---|---|
| `desktop_entry.py` | 轻量桌面入口；进入模块后才导入原 GUI |
| `system_workspace.py` | 配置归一化、连接、端口变更、回存和原子保存 |
| `system_workspace_ui.py` | Tk 框图、节点属性和单元窗口生命周期 |
| `system_report_worker.py` | 后台报告进程、取消与原子交付 |
| `web_app/frontend/src/SystemWorkspace.vue` | 独立网页架构首页及原 App 宿主 |
| `shared/power_architecture.js` | 网页共用框图几何与交互 |
| `pcs_workspace.py`、`pcs_reports.py` | 共用供电树校验、预算和报告编排 |
| `main.py`、`design_engine/` | 原单元计算、图表与仿真 |

沿用 `pcs.aux-workspace/1` 合同，保留旧工程 JSON 兼容；独立工程标记 `workspace_kind=power-system`。参数统一为 SI，保留 `__comp` 等元数据和内嵌曲线。不在 Tk 和 Vue 重写电源公式。

`tests/system_workspace_check.py` 检查回存、级联预算、循环、端口减少和实际 Tk 窗口切换；`tests/system_workspace_browser_check.cjs` 检查真实浏览器交互，设置 `SYSTEM_REPORT_QA=1` 同时验证报告下载。
