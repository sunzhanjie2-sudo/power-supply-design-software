## 2026-11-01 计算加速与界面响应

适用于个人项目的 Python 桌面版和本地 Python 网页服务。公司独立浏览器计算内核、LTspice 自身的仿真速度不在本次修改范围内。新版便携目录为 `releases/Windows-x64/20261101-calculation-speed/`。

### 优化位置

1. **耦合反激周期求解**：每段 RL 响应复用模态坐标，事件判断只求需要的电流；RMS 积分和波形取样按原有时间点批量计算。保留小时间步展开式、事件网格、20 点积分、收敛容差与波形密度。
2. **重复计算**：最多保留六个电气周期解。输入电压、负载、绕组矩阵、DCR、MOS/采样电阻、钳位及求解初值参与缓存键；改变电气条件会重新求解。读取后独立复制，热设计、磁件与器件检查继续按当前参数计算，取消或失败的解不入缓存。
3. **环路扫描**：状态空间模型分批求解原有的 6000 个频点，减少逐点 Python 调用；临时矩阵按约 8 MiB 预算分块，不转成高阶传递函数或删减极点。自动整定的相位扫描也使用同一方法。
4. **有源钳位正激**：逐步积分复用二极管关联矩阵、有效状态键及固定输入项，保留步长与收敛条件。
5. **报告数据准备**：同一份报告中，仅当两端输入条件和手动 MOS 工况相同时复用效率扫描，两端结果仍独立保存。不同输入电压或不同手动栅极参数分别计算。
6. **界面响应**：提示框关闭仅遍历正在显示/等待显示的提示；参数排版不再递归执行全部空闲绘图；批量载入先完成当前排版再启动计算。GUI 工作线程在已有取消检查点短暂让出执行时间，CLI 和网页批量求解不增加这类等待。器件表读取已发布的计算快照，计算中标记过期，避免切页时反复读取全部输入控件。

### 本机测速

对比基线为 Git `deffb59`。相同 Windows 电脑、Python 3.13.6、数值库线程设置、内置算例及输出内容。依赖导入预热后，首次求解每次清除数值缓存，重复求解保留缓存，均取三次中位数。这里的时间是计算服务调用时间，不是 EXE 冷启动时间，也不包含屏幕绘图或交叉调整率全角点扫描。

| 算例 | 首次计算：原版 → 新版 | 同参数重复：原版 → 新版 |
|---|---:|---:|
| 三路 CCM 反激 | 1.489 → 0.915 s | 1.480 → 0.226 s |
| 三路耦合反激 | 1.480 → 0.881 s | 1.496 → 0.131 s |
| 三路有源钳位正激 | 1.211 → 0.981 s | 0.301 → 0.270 s |
| 92 W QR 反激 | 35.5 → 36.1 ms | 36.9 → 32.7 ms |
| Buck 电压控制 | 163 → 42.7 ms | 160 → 39.4 ms |
| Buck 峰值电流控制 | 158 → 41.5 ms | 155 → 39.0 ms |
| Boost 峰值电流控制 | 164 → 42.3 ms | 156 → 38.2 ms |

Buck/Boost 的完整环路扫描由约 125–128 ms 降至 8.5–9.6 ms；三路反激由约 73–75 ms 降至 14 ms。QR 本来计算很短，本轮没有显著的单次求解提升，毫秒级差异受运行噪声影响。

两端输入与效率曲线的报告数据准备，三路 CCM 反激从 11.14 s 降至 6.26 s，三路耦合反激从 9.17 s 降至 2.46 s，有源钳位正激从 49.11 s 降至 39.33 s。此项每例测一次，**不包含 Word/Excel 排版、图像生成、交叉调整率扫描或 LTspice 运行**，不能作为完整报告总耗时。

六路耦合算例的桌面响应回归中，后台计算期间 Tk 心跳最大间隔约 39 ms；包含配置载入、排版及重绘的全过程最大间隔约 775 ms。相同加强检测曾捕获本次界面修正前超过 3 s 的停顿。该测试是可响应性检查，包含约 4.64 s 的界面与计算流程，不与上表纯服务测速混用，也不保证所有机器或重绘操作始终低于此值。

默认单路源码进程的内存未明显增加：启动稳定后工作集约 155 MiB，依次浏览主要页面后约 250 MiB，前后均为 12 个画布。首次有效设计在本轮单次采样中由 4.21 s 变为 3.17 s，但其中导入时间受文件缓存影响，不能据此承诺 EXE 冷启动加速比例。

### 精度与回归结果

- 七个内置算例逐项对比公开计算结果，共 **2,164,596 项数值**，相对容差 `2e-8`、绝对容差 `2e-10` 内全部一致；未通过减少频点、波形点或放宽收敛条件换取速度。
- 最终数值回归 55 项通过，覆盖矩阵响应、SISO/MIMO 频响、精确极点处理、缓存失效/隔离/取消、输入范围、QR、Buck/Boost 和正激；多路环路另外 17 项通过。
- 最终界面及导出相关回归 24 项通过，包含六路心跳、连续改参、取消、延迟排版时取消、器件信息刷新、折叠、大字号及补偿参数导出。
- 历史测试有六项旧断言仍失败：`coupled_integration_check.py` 的三个旧输出电压/表格格式断言，以及 `parameter_ui_check.py` 的三个旧分类/固定 Vin 控件断言。在未修改的基线源码上同样复现；未将这些测试标为通过或修改预期来掩盖失败。

## 本次改变

1. 数值库默认单线程。程序的小规模数值运算不再默认唤起两套各 16 线程的 OpenBLAS 池，减少线程栈提交和竞争；只在本进程启动时设置，未修改系统环境、注册表或其他程序。
2. 隐藏图表不保留整幅像素缓冲。普通页面保留图元和数据，显示时重建；未访问的画布只分配极小的 Tk 图片。
3. 多路结果按视口绘制。功率级、器件损耗、电容页保留全部 OUT 及滚动高度，只为可见卡片创建完整画布，移出视口释放。滚动/缩放合并调度，每次回调最多新画一路；滚回需短暂重画，不能据此认为其他输出被删掉。
4. 限制快照缓存和邮箱。计算缓存同时受最多 3 项及估算 64 MiB 限制，按最近使用淘汰；超大结果仍正常计算与发布，不缓存。不再在空闲工作线程、旧页面或未读消息中额外保留上一代大波形。
5. 环路按需计算。拓扑首屏不预加载 `control`；首次进入⑤环路或⑩评审可能短暂显示加载提示。同参数只重复绘图，不重复求 Bode 数值；电气参数变化后使用新结果。依赖加载失败会停止轮询并显示原因。

缓存预算是对缓存对象和数组的估计，不包含 GUI 当前结果、图形、库、Python 分配器或工程评审 A/B 快照，不是整个进程的内存硬上限。单路/六路往返后的工作集可能保留一部分已申请内存，不能要求任务管理器每次立即回到刚启动值。

## 实测口径

在本机 Windows、Python 3.13.6、同一 1400×900 测试窗口、独立新进程下采样。默认设计为原 40W CCM 反激；六路工况使用 30/12/5/3.3/24/15 V、20/8/4/2/4/2 W，矩阵耦合关闭。浏览功率级、器件、磁件、电容、环路、效率、拓扑各两遍，回到拓扑页测量。窗口由测试创建，未读取或关闭用户现有窗口。

| 场景/指标 | 优化前 | 优化后 |
|---|---:|---:|
| 默认启动稳定后，工作集 RSS | 264 MiB | 154 MiB |
| 默认启动稳定后，线程数 | 41 | 8 |
| 六路浏览主要页面后，工作集 RSS | 497 MiB | 267 MiB |

工作集 RSS 表示当时驻留物理内存；Windows 私有提交量是另一指标，不能把优化前的约 1.4 GiB 说成实际占用的物理内存。数字取整，属同机诊断，不是其他电脑的性能承诺。原始测量保存在开发目录 `_tmp_resource_qa/`。这些是源码新进程数据，不等同于 EXE 冷磁盘启动测量。

最终六路测试中，首次进入功率级页由约 3.17 s 变为 0.64 s，电容页由约 2.09 s 变为 0.45 s。每次包含约 0.2 s 的稳定等待，故不是纯绘图耗时；后台负载也会影响结果。首次环路页反而需要额外加载时间（本轮约 2.05 s），这是将启动开销移到实际使用时的取舍；重复切页也可能因图像缓冲重建比过去稍慢。没有证据表明原空闲 CPU 占用异常，本版不承诺一个固定 CPU 百分比。

## 不变的内容与边界

- 未降低采样点数、矩阵求解容差、绕制几何精度或报告图片分辨率，未改变电气公式和默认参数。计算说明 Word 没有因资源优化而修改公式。
- Word 使用独立图形生成，不依赖屏幕上是否已滚动到某一路；隐藏/释放 GUI 缓冲不省略报告内容。
- 未完成环路加载/计算前，相关检查为待算或待复核，不默认通过。进入环路/工程评审补齐当前设计检查；API 与完整报告保持完整计算。
- 多路两两耦合周期稳态仍可能较慢。输入防抖、单数值工作线程、最新任务覆盖和协作式取消继续生效，改善可交互性不等于所有物理求解瞬间完成。
- 导出、库内部单次调用和复杂绘图仍可能有短暂主线程操作；本次并非所有功能彻底异步化。

## 可选线程覆盖

一般无需设置。如需在专用计算机上对比，可在启动前设置进程环境变量 `POWER_DESIGN_NUM_THREADS` 为 1–32 的整数；默认 1，非法值回到 1。直接设置的 `OPENBLAS_NUM_THREADS`、`OMP_NUM_THREADS`、`MKL_NUM_THREADS` 等库环境变量优先保留。更大线程数不保证更快，且可能增加提交量；不建议为此修改系统级环境。

嵌入已有 Python 进程且 NumPy 已加载时，启动默认不能追溯收回已经创建的原生线程池；请以全新进程测试。
